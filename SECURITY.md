## Reporting a Vulnerability

If you discover a security vulnerability within Sovereign, please report it responsibly.

### How to Report

1. **Do NOT** open a public issue for security vulnerabilities
2. Email the maintainer directly or use GitHub's private vulnerability reporting feature
3. Include:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact assessment
   - Suggested fix (if any)

### What to Expect

- Acknowledgment within 48 hours
- Status update within 7 days
- Fix timeline communicated once assessed

### Scope

The following are in scope for security reports:
- Smart contract (canister) vulnerabilities
- Authentication/authorization bypasses
- Data exposure or leakage
- Injection attacks
- Cryptographic weaknesses

### Anti-Extraction Protection

Per Article VII of the SAPL license, the following are prohibited and should NOT be submitted as "research":
- Reverse engineering of internal architectures
- Model inversion attacks
- Knowledge distillation attempts
- API probing for hidden capabilities

Violations of Article VII constitute trade secret misappropriation.
